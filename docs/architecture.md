# 架构说明：长期运行的 AI Agent 如何避免“看起来正确”
版本：公开审稿草案 v0.1；不包含私人交易参数。

## 一、从语言模型走向有约束的工作流

单靠一次性 Prompt 难以解决持续运行中的四种情况：之前做过的判断如何保留、新输入与旧输入如何区分、外部工具数据不完整时怎么办、模型如何知道哪些动作未获授权。

VEP 的工程化方向是把 Agent 拆为三个可检查的部分：**确定性数据准备、带条件的模型推理、可追溯的结果归档**。AI 不应因为能组织语言，就得到制造事实或执行敏感动作的权限。

## 二、模块责任（源于本地实际项目）

| 模块 | 职责 | 安全边界 |
| --- | --- | --- |
| 输入与快照 | 账户、对象、行情、时间标记 | 旧快照不能被提升为当前事实 |
| 证据适配器 | 从工具/接口收集并标准化 | 数据源、时区、截止时间都要记录 |
| 事实门禁 | 检查缺失、过期、来源不符 | 关键字段失败时阻断正式分析 |
| 模型推理 | 解释相互矛盾的证据，形成研究意见 | 不能捏造未取得的数据 |
| 结构化报告 | 固定栏目、审计状态、证据缺口 | 栏目齐全不代表内容准确 |
| 任务调度 | 分阶段提醒、检查是否可执行 | 定时任务不自动取得投资动作权限 |
| 持久记忆 | 上次状态、变更原因、审阅记录 | 不覆盖用户最新确认事实 |

## 三、证据优先级与新鲜度

每条关键输入应带有：证据标识、数据来源、产生时间、对应的业务日期、验证状态，以及适用范围。

一份旧报告可以为今日提供背景，但不能自动成为今日成交、持仓或价格的依据。缺失信息用 `MISSING`、`REFERENCE_ONLY` 或类似状态显示，不能填入“看起来合理”的数值。

## 四、会话连续性

运行步骤一般是：读取最新已确认状态 → 明确来源和版本 → 合并新增证据 → 检查冲突 → 推理/报告 → 经审核归档。

中断后恢复不能只靠聊天记忆；要回到持久化事实与用户最近一次确认状态。必要时进入等待/补数据状态，而不是悄悄补全。

## 五、市场/任务域隔离

不同市场的行情、交易约束、指标时间定义和账户状态不同，不能因为“同属投资”就共用全部默认规则。工程上应有隔离的数据域与映射层；这是通用的软件设计原则，公开稿不包含具体市场参数。

## 六、模型与权限隔离

采集程序负责取得可核对的数据；大模型根据统一输入解释。候选清单并不等于真实持仓，观察提醒并不等于买卖建议，报告生成更不等于自动下单授权。

## 七、尚未完成的验证

本版尚未给出：公开可运行的最小演示、完全匿名的测试输入、端到端评估、故障注入复现、成本/延迟数据。完成这些之后，才适合发布为可安装软件。
